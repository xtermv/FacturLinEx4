ESTADO

Estructura funcional basada en la configuración modernizada v9. Las rutas y valores concretos deben adaptarse a cada instalación.

2.1 Orden recomendado de configuración #

  1. Comprobar la conexión con la base de datos principal.
  2. Configurar empresa, tienda y puesto.
  3. Revisar series, numeraciones y tipos de documento.
  4. Configurar impresoras, plantillas y generación de PDF.
  5. Configurar el correo electrónico y realizar una prueba de envío.
  6. Revisar IVA, entorno de producción y opciones de VeriFactu.
  7. Configurar rutas de informes, recursos, iconos y copias de seguridad.
  8. Crear o revisar usuarios, permisos y formas de pago.
  9. Realizar una copia de seguridad y una venta completa de prueba.

2.2 Conexión con MariaDB #

La configuración de conexión debe identificar correctamente el servidor, puerto, base de datos, usuario, contraseña y juego de caracteres. La pantalla de Configuración dispone de botones de prueba para la base principal y para el sistema de información común.

  • El servidor responde desde el equipo donde se ejecuta FacturLinEx.
  • La base de datos indicada existe.
  • El usuario dispone de los permisos necesarios.
  • El juego de caracteres es compatible con los datos existentes.
  • La prueba de conexión finaliza correctamente.
!
PRECAUCIÓN

No cambiar charset, collation o motor de tablas en producción sin copia previa y sin comprobar las tablas afectadas. Las mezclas de collations pueden provocar errores en consultas JOIN.

2.3 Empresa, tienda y puesto #

Los datos de empresa se utilizan en documentos, informes y comunicaciones. La tienda determina el conjunto de tablas y configuraciones sobre el que se trabaja. El puesto identifica la terminal de venta y puede aparecer en registros históricos.

ElementoComprobaciones
EmpresaRazón social, NIF, dirección, datos de contacto y datos fiscales.
TiendaCódigo, descripción, rutas y correspondencia con las tablas de la instalación.
PuestoLetra o identificador visible en Ventas y coherente con el registro histórico.
UsuarioNombre, credenciales, permisos y asociación correcta a las operaciones.

2.4 Series y numeraciones #

Cada tipo de documento utiliza series y contadores. Las series permiten separar tiendas, ejercicios, documentos simplificados, rectificativas y otros circuitos.

TipoEjemplos habitualesUso
NormalA26, B26...Facturas o documentos completos.
SimplificadaFS-A26Facturas simplificadas o tickets fiscales.
Rectificativa normalR26Corrección de factura normal.
Rectificativa simplificadaFS-R26Corrección de factura simplificada.
!
CRÍTICO

No reiniciar ni alterar manualmente una numeración que ya haya generado documentos fiscales sin analizar sus consecuencias. Puede producir duplicidades, huecos incoherentes o problemas de trazabilidad.

2.5 Impresión, PDF y correo #

FacturLinEx puede imprimir tickets e informes, generar documentos PDF y enviarlos por correo. Deben revisarse las impresoras, plantillas, rutas de salida y credenciales de correo.

  • Impresora de tickets seleccionada y probada.
  • Impresora de informes o facturas seleccionada.
  • Plantillas .lrf localizadas y compatibles con los campos utilizados.
  • Ruta de PDF con permisos de escritura.
  • Servidor SMTP, puerto, seguridad, usuario y remitente configurados.
  • Prueba de envío realizada y mensaje informativo visible por encima de otros controles.

2.6 VeriFactu #

Antes de activar el entorno de producción, deben revisarse los datos de empresa, las series, la generación de fechas y horas, el encadenamiento de registros y la configuración de envío. Los estados y errores se consultan en el monitor de la cola.

i
PRODUCCIÓN

La indicación Sistema en producción debe ser visible y destacada. No activar el entorno real hasta completar pruebas controladas.

2.7 Copias de seguridad iniciales #

Debe existir al menos una copia completa antes de comenzar a trabajar y otra antes de cualquier cambio importante. Una copia solo es fiable cuando puede restaurarse correctamente.

  • Guardar una copia fuera del servidor principal.
  • Conservar varias fechas, no únicamente la última.
  • Registrar qué versión del programa y de la base de datos corresponde a cada copia.
  • Probar periódicamente la restauración en un entorno separado.
