Ventas y TPV

ESTADO

Basado en la versión de Ventas validada como final y estable con atajos en la línea inferior. Los circuitos rectificativos continúan requiriendo pruebas específicas.

5.1 Objetivo de la pantalla #

La pantalla de Ventas permite identificar al cliente, introducir artículos, aplicar cantidades y descuentos, totalizar, cobrar, emitir documentos y gestionar situaciones especiales. Está pensada para funcionar con teclado, ratón y pantalla táctil.

5.2 Preparación antes de vender #

  • La tienda y el puesto mostrados son correctos.
  • El usuario activo es el adecuado.
  • La serie de trabajo corresponde al tipo de documento.
  • La impresora de tickets está disponible.
  • La base de datos tiene conexión.
  • El teclado de productos, si se utiliza, carga los grupos e imágenes esperados.

5.3 Selección del cliente #

En una venta genérica puede utilizarse el cliente predeterminado. Para facturas, créditos, albaranes o condiciones especiales, debe seleccionarse la ficha correcta.

AcciónAtajo o método
Ir al código de clienteCtrl + O
Ir al nombre de clienteCtrl + U
Crear o iniciar cliente nuevoCtrl + N, según la versión validada
Buscar por NIFUtilizar la búsqueda y seleccionar entre coincidencias si existen varias.
i
COMPROBACIÓN

Antes de totalizar una factura completa, revisar nombre, NIF, dirección y serie. Corregir después puede requerir anulación o rectificativa.

5.4 Introducción de artículos #

  1. Situar el foco en el campo de código o EAN.
  2. Leer el código con escáner o escribirlo manualmente.
  3. Confirmar la descripción, cantidad, PVP, IVA y descuentos mostrados.
  4. Modificar cantidad o precio únicamente cuando el usuario esté autorizado.
  5. Repetir hasta completar la venta.

Las líneas de venta deben reflejar el precio real aplicado. Cuando existe descuento, las estadísticas deben considerar el precio efectivo vendido, no únicamente el PVP original de tarifa.

5.5 Códigos varios #

El panel de código vario permite introducir una descripción, cantidad y PVP para conceptos no vinculados a un artículo estándar. El orden de tabulación debe ser Descripción, Cantidad y PVP, permitiendo trabajar con ENTER o TAB.

i
USO CONTROLADO

Los códigos varios reducen trazabilidad de stock y estadísticas. Utilizarlos solo cuando no exista un artículo adecuado o en casos justificados.

5.6 Teclado virtual y teclado de productos #

El teclado virtual cambia entre modo numérico y alfanumérico según el campo activo. Puede ocultarse sin bloquear el formulario. El teclado de productos se construye por grupos y orden configurado, relacionando los botones con artículos reales.

  • Cantidad y precio: teclado numérico.
  • Descripción y búsquedas: teclado alfanumérico.
  • El botón Ocultar minimiza el teclado, no debe cerrar ni bloquear la venta.
  • Los productos pueden activarse o desactivarse de forma múltiple desde su configuración.
  • La búsqueda para añadir productos puede realizarse por descripción o EAN.

5.7 Totalización y cobro #

  1. Revisar las líneas y el total.
  2. Abrir la totalización con la tecla o botón indicado en la barra inferior.
  3. Seleccionar la forma de pago.
  4. Introducir la entrega. El foco debe pasar automáticamente al campo correspondiente cuando proceda.
  5. Comprobar el cambio.
  6. Confirmar e imprimir o generar el documento.
i
VISIBILIDAD

La ventana de cobro debe tener un marco diferenciado. Los textos Entrega y Cambio deben aparecer claramente separados del Total.

5.8 Ticket, albarán y factura #

DocumentoUso habitualConsideraciones
Ticket / factura simplificadaVenta inmediata con requisitos simplificados.Puede utilizar series FS-. Revisar límites y datos fiscales aplicables.
AlbaránEntrega pendiente de facturación.Normalmente debe anularse con otro albarán, no como ticket.

5.9 Aparcar y recuperar ventas #

Cuando una operación debe quedar pendiente, puede aparcarse y recuperarse posteriormente. Antes de recuperar, comprobar puesto, cliente, líneas y estado de la operación para evitar duplicidades.

5.10 Devoluciones y anulaciones #

Las devoluciones pueden generar líneas negativas y activar el circuito rectificativo. El usuario debe indicar si el origen es simplificado o normal, la serie y número originales y el motivo obligatorio.

i
ALBARANES

Un albarán debe anularse normalmente mediante otro albarán. Si se intenta tratar como ticket, puede solicitar serie y número que no corresponden al circuito original. Evitar esta práctica salvo caso excepcional controlado.

  • Las ventas mixtas con líneas positivas y negativas pueden requerir separación documental.
  • Las rectificativas manuales sin histórico deben vigilar posibles duplicidades.
  • La búsqueda del documento original puede exigir coincidencia del cliente.
  • Después de emitir una rectificativa, revisar impresión, histórico y cola VeriFactu.

5.11 Cierre seguro con ESC #

En la pantalla principal, ESC debe realizar la misma acción que Cerrar. Si existe un panel de totalización, teclado, selector, mensaje o edición pendiente, debe cerrarse o cancelarse primero ese elemento.

5.12 Comprobación de una venta #

  • Cliente correcto.
  • Artículos, cantidades y descuentos correctos.
  • IVA y totales coherentes.
  • Forma de pago correcta.
  • Serie y número adecuados.
  • Documento impreso o PDF legible.
  • Registro histórico creado.
  • Cola VeriFactu revisada cuando proceda.
